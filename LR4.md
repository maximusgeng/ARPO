# Лабораторная работа № 4. Автоматизация тестирования в CI/CD

**Цель** – автоматизировать проверки Unity в режимах EditMode и PlayMode и запускать сборку Docker-образа только после успешного тестирования.

**Вариант 7.** Новый экземпляр `PlayerController` должен иметь состояние прыжка `JumpState.Grounded`. Тест создаёт временный неактивный объект, добавляет игровой компонент и проверяет значение `jumpState` до первого кадра. Объект удаляется в блоке `finally`.

## Сборки и тесты

Игровые скрипты находятся в сборке `GameAssembly`, которая ссылается на Input System и Cinemachine. Сборки `Tests` и `PlayModeTests` используют игровой код. Для `Tests` установлена платформа `Editor`.

| Режим | Тест | Проверка | Локальный результат |
|---|---|---|---|
| EditMode | `EditMode_PlayerTag_IsCorrect` | Объект Player в SampleScene, его тег и компоненты PlayerController и Health | Passed |
| EditMode | `EditMode_PlayerJumpState_StartsGrounded` | Начальное состояние прыжка по варианту 7 | Passed |
| PlayMode | `PlayMode_PlayerTakesDamage_HealthDecreases` | При 3 HP первые два попадания оставляют игрока живым, третье убивает | Passed |

Тесты выполнены через Unity Test Framework в Unity 6000.6.0f1. Для отрицательной проверки ожидаемое значение временно заменено на `InFlight`. Тест завершился с ошибкой сравнения, поскольку фактическим значением было `Grounded`. Затем ожидание `Grounded` восстановлено и EditMode запущен повторно.

В редакторе эти проверки доступны в **Window → General → Test Runner**. Выберите вкладку **EditMode** или **PlayMode** и нажмите **Run All**.

## GitHub Actions

`sanity_check` → `run_tests` → `build_docker_image` и `mirror_repo`.

Задача `run_tests` запускает оба режима через GameCI CLI в контейнере Unity и выгружает файлы результатов как артефакт `test-results`. Сборка, публикация и зеркалирование запускаются только для push в `main` после успешного тестирования. Pull request запускает проверку проекта и тесты.

В репозитории требуется настроить секреты `UNITY_LICENSE`, `UNITY_EMAIL` и `UNITY_PASSWORD`. Пока секреты отсутствуют, GitHub Actions останавливается на проверке конфигурации. Облачное выполнение тестов и проверка блокировки сборки при падении теста ещё не подтверждены.

## Контрольные вопросы

1. **Различие EditMode и PlayMode.** EditMode выполняет проверки в редакторе без игрового цикла. PlayMode запускает игровую среду и позволяет ждать кадры и проверять события жизненного цикла компонентов.
2. **Роль asmdef.** Файл задаёт границы сборки, её зависимости и целевые платформы. Ссылка на GameAssembly даёт тестам доступ к игровым типам.
3. **Зачем сборке Docker-образа needs: run_tests.** GitHub Actions запускает зависимую задачу только после успешного завершения тестов. При падении проверки сборка и публикация пропускаются.
4. **Как действует includePlatforms.** Значение Editor ограничивает сборку редактором и в данной структуре выделяет тесты EditMode. PlayModeTests не имеет этого ограничения и может участвовать в запуске PlayMode.
